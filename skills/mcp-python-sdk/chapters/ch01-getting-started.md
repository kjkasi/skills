# Chapter 1: Getting Started

## Core Idea
The MCP Python SDK lets you build a server that exposes tools, resources, and prompts to LLM clients with minimal boilerplate: one decorator per primitive, type hints become the schema, and `Client(mcp)` connects in-memory for testing.

## Frameworks Introduced
- **MCPServer**: The high-level server class that wraps protocol details. Use `from mcp.server import MCPServer` (v2) or `from mcp.server.fastmcp import FastMCP` (v1).
  - When to use: Always. Every MCP server starts with `MCPServer`.
  - How: `mcp = MCPServer("Name")`, then decorate functions with `@mcp.tool()`, `@mcp.resource(uri)`, `@mcp.prompt()`.
- **Client**: In-memory or network client for talking to servers. Use `from mcp import Client`.
  - When to use: Testing servers, building applications that consume MCP servers, or connecting to a real host.
  - How: `async with Client(mcp) as client:` for in-memory, `Client("http://...")` for HTTP, `Client(StdioServerParameters(...))` for subprocess.

## Key Concepts
- **Host**: The LLM application (Claude, IDE, agent runtime) the user talks to.
- **Client**: Lives inside the host, speaks MCP to one server. The host runs one client per server.
- **Server**: What you build with this SDK. Exposes things to clients; never talks to the model directly.
- **Tools**: Model-controlled actions the model decides to call (like a POST with side effects).
- **Resources**: Application-controlled data the host loads into context (like a GET, read-only).
- **Prompts**: User-controlled message templates invoked by name (slash commands, menu entries).
- **Capabilities**: The server's declaration of which request families it answers, auto-generated by `MCPServer`.

## Mental Models
1. **Decorator-as-registration**: `@mcp.tool()` is the entire registration. Name from the function, description from the docstring, schema from type hints. No JSON Schema, no request handler, no capability declaration needed.
2. **Three primitives, three controllers**: Tools are model-controlled, resources are application-controlled, prompts are user-controlled. This split is the architectural foundation.
3. **In-memory testing**: `Client(mcp)` connects to the server object directly—no subprocess, no port, no transport. Same idea as FastAPI's `TestClient`.
4. **Import paths matter**: `from mcp import Client` and `from mcp.server import MCPServer`—there is no `from mcp import MCPServer`.

## Anti-patterns
- **Forgetting `()` on decorators**: `@mcp.tool` instead of `@mcp.tool()` raises `TypeError` at import time. Python hands your function to the `name=` parameter.
- **Relative paths for hosts**: The host launches your server from its working directory. Always use absolute paths in host configuration.
- **`print()` in stdio servers**: stdout belongs to the protocol. Use `logging` to stderr instead.
- **Using `from mcp.server.fastmcp import FastMCP`**: This is v1 only. v2 uses `from mcp.server import MCPServer`.

## Code Examples
```python
# server.py
from mcp.server import MCPServer

mcp = MCPServer("Demo")

@mcp.tool()
def add(a: int, b: int) -> int:
    """Add two numbers."""
    return a + b

@mcp.resource("greeting://{name}")
def greeting(name: str) -> str:
    """Return a greeting."""
    return f"Hello, {name}!"

@mcp.prompt()
def summarize(text: str) -> str:
    """Summarize the given text."""
    return f"Please summarize: {text}"

if __name__ == "__main__":
    mcp.run()
```

## Worked Example
Testing a server in-memory:
```python
import asyncio
from mcp import Client
from server import mcp

async def main():
    async with Client(mcp) as client:
        print(client.server_capabilities.model_dump(exclude_none=True))
        result = await client.call_tool("add", {"a": 1, "b": 2})
        print(result.content)  # [TextContent(text='3')]

asyncio.run(main())
```
The capabilities dict shows `tools`, `resources`, and `prompts`—all declared automatically. The tool returns both `content` (text for the model) and `structured_content` (typed data for the application).

## Key Takeaways
1. One decorator per primitive: `@mcp.tool()`, `@mcp.resource(uri)`, `@mcp.prompt()`. Name, description, and schema come from the function itself.
2. `Client(mcp)` is your in-memory test harness from day one—no subprocess, no port, no transport configuration.
3. The SDK reads type hints as the schema, so bad arguments are rejected before your function runs.
4. `mcp.run()` blocks for the server's lifetime. Put it under `if __name__ == "__main__":` to avoid starting on import.
