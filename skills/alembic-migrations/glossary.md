# Glossary

- **alembic_version** — Database table tracking current migration revision(s); can have multiple rows during branch merges (Ch 2)
- **autogenerate** — Feature comparing ORM MetaData against live database to produce candidate migrations (Ch 3)
- **base** — The starting revision in a migration chain; `down_revision = None` (Ch 2)
- **batch_alter_table** — Operations context for SQLite-compatible "move and copy" table recreation (Ch 6)
- **branch label** — Named alias for a revision chain; enables `branchname@head` syntax (Ch 7)
- **branch point** — A revision with two or more descendants sharing it as parent (Ch 7)
- **compare_type** — env.py flag controlling whether column type changes are detected by autogenerate (Ch 3)
- **compare_server_default** — env.py flag controlling server default comparison in autogenerate (Ch 3)
- **ConfigParser** — Python config parser used by alembic.ini; requires percent-sign doubling for literal `%` (Ch 1)
- **copy_from** — Parameter on `batch_alter_table` providing a pre-fabricated Table for offline batch mode (Ch 6)
- **depends_on** — Migration directive declaring cross-branch dependency without merging (Ch 7)
- **down_revision** — Pointer to parent revision in the migration chain; forms a linked list / DAG (Ch 2)
- **env.py** — Customizable Python script run on every Alembic invocation; controls DB connection and migration execution (Ch 1)
- **file_template** — Naming scheme for generated migration files; supports tokens like `%(rev)s`, `%(slug)s`, `%(year)d` (Ch 1)
- **head** — The most recent revision(s) in the migration chain; ambiguous with multiple heads (Ch 2)
- **heads** — All current head revisions at once; used when multiple branches exist (Ch 7)
- **include_name** — Callable hook `(name, type_, parent_names) -> bool` filtering schemas/tables from autogenerate (Ch 3)
- **include_object** — Callable hook `(object, name, type_, reflected, compare_to) -> bool` for fine-grained autogenerate filtering (Ch 3)
- **merge point** — A revision with multiple `down_revision` entries joining branches into a single head (Ch 7)
- **MetaData** — SQLAlchemy object containing Table definitions; `target_metadata` in env.py drives autogenerate (Ch 3)
- **naming_convention** — Dictionary on MetaData mapping constraint types to name templates; ensures named constraints (Ch 5)
- **op.f()** — Bypass naming convention tokenization for literal constraint names in operations (Ch 5)
- **offline mode** — Generating SQL scripts instead of executing migrations; enabled via `--sql` flag (Ch 4)
- **operations** — Migration directives (`op.*`) for DDL: create_table, add_column, drop_constraint, etc. (Ch 8)
- **post_write_hooks** — Scripts/functions run on newly generated revision files (e.g., Black, ruff formatters) (Ch 3)
- **PRAGMA FOREIGN KEYS** — SQLite setting that must be disabled during batch operations (Ch 6)
- **render_as_batch** — env.py flag making autogenerate produce batch-compatible `batch_alter_table` output (Ch 6)
- **recreate='always'** — Force move-and-copy on all backends, not just SQLite (Ch 6)
- **revision** — Unique ID for a migration file; linked to parent via `down_revision` (Ch 2)
- **script.py.mako** — Mako template for generating new migration file structure (Ch 1)
- **sqlalchemy.url** — Database connection string in alembic.ini; must percent-escape special chars (Ch 1)
- **stamp** — Mark a database at a specific revision without running migrations (Ch 9)
- **target_metadata** — The MetaData object(s) in env.py representing desired schema for autogenerate (Ch 3)
- **version_locations** — Multiple directories for version files; enables separate branch directories (Ch 7)
