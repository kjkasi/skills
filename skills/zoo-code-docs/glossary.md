# Zoo Code Glossary

**`@problems`** — Imports all VS Code Problems panel errors/warnings with file paths and line numbers (Ch 3)
**`@terminal`** — Captures last command output from the terminal buffer (Ch 3)
**`@git-changes`** — Shows git status and diff of uncommitted changes (Ch 3)
**`/architect`** — Slash command to switch to Architect mode (Ch 5)
**`/ask`** — Slash command to switch to Ask mode (Ch 5)
**`/code`** — Slash command to switch to Code mode (Ch 5)
**`/debug`** — Slash command to switch to Debug mode (Ch 5)
**`/orchestrator`** — Slash command to switch to Orchestrator mode (Ch 5)
**`/<command-name>`** — Slash commands execute predefined actions using `/` prefix (Ch 3)
**`apply_diff`** — Surgical single-file edit tool using fuzzy matching with SEARCH/REPLACE format (Ch 9)
**`apply_patch`** — Multi-file unified diff patch tool for atomic batch operations (Ch 9)
**`ask_followup_question`** — Structured clarification tool with suggested answers; available in all modes (Ch 12)
**`attempt_completion`** — Signals task completion with optional demo command (Ch 12)
**Auto-approve** — Optional setting to skip manual approval for trusted operations (Ch 4)
**Auto-Approved Request Limit** — "Max Requests" setting that caps consecutive unapproved API calls (Ch 14)
**Background Editing** — Experimental setting that silences automatic diff views; files modify silently (Ch 8)
**Checkpoints** — Experimental feature enabling file revert to previous state (Ch 16)
**Claude Sonnet 4.5** — Recommended starting model balancing power and cost (Ch 1)
**Code Mode** — Default mode with full access to read, edit, command, and MCP tools (Ch 5)
**Codebase Indexing** — Semantic search using AI embeddings with Qdrant vector database (Ch 16)
**Context Budget** — The finite token space consumed by mentions; must be managed strategically (Ch 3)
**Context Poisoning** — Contaminated session context causing persistent incorrect outputs; unrecoverable within session (Ch 13)
**Context Window** — Maximum tokens the LLM can process including system prompt, history, and tool outputs (Ch 13)
**Concurrent File Reads** — Reading up to 100 files in a single request (default: 5) (Ch 6)
**Concurrent File Edits** — Batch multi-file diff approval, now enabled by default (Ch 8)
**Custom Instructions** — Persistent guidance files at global, workspace, and mode-specific levels (Ch 6)
**Custom Mode** — User-defined mode with tailored tool access, file permissions, and behavior (Ch 5)
**Custom Tools** — TypeScript/JavaScript tools in `.roo/tools/` that auto-approve on execution (Ch 8)
**`edit`** — Search-and-replace tool; replaces first occurrence by default (Ch 10)
**`edit_file`** — Replaces exactly one uniquely-identified occurrence; errors on ambiguous matches (Ch 10)
**Enhance Prompt** — Wand-icon feature that refines prompts using conversation history context (Ch 6)
**Error Details Modal** — Diagnostic export panel (basic or detailed) for troubleshooting (Ch 16)
**execute_command** — Runs CLI commands via VS Code terminal with security validation (Ch 11)
**Input Tokens** — Tokens in your prompt including system prompt, instructions, and context (Ch 14)
**Iterative Approval Loop** — Every action requires explicit user confirmation before execution (Ch 1)
**Lightweight Model** — Smaller, cheaper model for simple tasks; reserve large models for complex work (Ch 14)
**`list_files`** — Tool for listing directory contents (Ch 4)
**Local Model Provider** — Ollama or LM Studio running models on local hardware (Ch 15)
**Max Tokens** — Shared budget between thinking tokens and conversation history; tune per mode (Ch 17)
**MCP (Model Context Protocol)** — Standardized AI protocol for orchestrating external tools with context (Ch 7)
**MCP Configuration** — Global or project-level (`.roo/mcp.json`) settings for MCP servers (Ch 7)
**`new_task`** — Spawns subtasks with parent-child relationships in isolated conversation contexts (Ch 11)
**Orchestrator Mode** — Strategic workflow mode that delegates subtasks via `new_task`; no direct tool access (Ch 5)
**Output Tokens** — Tokens generated by the AI including reasoning/thinking tokens (Ch 14)
**Parallel Repository Copies** — Multiple repo clones with separate Zoo Code instances for team-like workflows (Ch 17)
**Pattern: Contextual Communication** — Be specific with file paths, function names, expected outcomes (Ch 2)
**Pattern: Human-in-the-Loop** — Zoo Code proposes actions, you approve/reject before execution (Ch 1)
**Pattern: Read-before-Write** — Zoo Code reads files before editing as a safety pattern (Ch 4)
**Pattern: Think-then-Do** — Guide through Analyze → Plan → Execute → Review for each step (Ch 13)
**Provider** — Backend LLM service (Anthropic, OpenAI, OpenRouter, etc.) powering Zoo Code (Ch 1)
**Prompt Caching** — Provider feature caching repeated prompts for cost/latency reduction (Ch 13)
**read_command_output** — Retrieves truncated command output with pagination or search modes (Ch 11)
**read_file** — Reads file content with slice or indentation mode; supports images, PDFs (Ch 9)
**Rule Loading Order** — Global → Workspace (overrides) → Mode-specific (scoped) (Ch 6)
**`rooignore`** — Gitignore-like file access control scoped to workspace root (Ch 6)
**`search_replace`** — Simplest replacement tool; errors on multiple matches by design (Ch 10)
**`search_files`** — Regex-based codebase search using Ripgrep; respects .gitignore by default (Ch 10)
**Secondary Sidebar** — VS Code sidebar placement keeping Zoo Code visible alongside other panels (Ch 2)
**`skill`** — Loads specialized instruction sets resolved by priority across project and global paths (Ch 12)
**Sticky Models** — Each mode remembers last-used model; auto-switches on mode change (Ch 5)
**System Prompt** — Dynamically generated foundation containing role, tools, rules, and custom instructions (Ch 13)
**Temperature** — Controls output randomness (0.0–2.0); 0.0 optimal for code (Ch 6)
**Tool Group** — Four capability categories: read, edit, command, mcp (Ch 5)
**Tool Proposal** — XML-formatted representation of what Zoo Code wants to do (Ch 4)
**Transport Layer** — MCP communication mechanisms: STDIO, Streamable HTTP, SSE (Ch 7)
**`update_todo_list`** — Replaces entire markdown checklist; always include all items (Ch 12)
**`use_mcp_tool`** — Executes tools on MCP servers with full argument passing (Ch 12)
**`write_to_file`** — Creates new files or completely replaces content; requires line_count (Ch 9)
