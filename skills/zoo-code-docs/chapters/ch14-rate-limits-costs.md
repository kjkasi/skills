# Chapter 14: Rate Limits & Costs

## Core Idea
Understanding token usage, cost calculation, and optimization strategies helps you manage API expenses and maintain a smooth, cost-effective experience with Zoo Code.

## Key Concepts
- **Input Tokens**: Tokens in your prompt—system prompt, instructions, and provided context (file contents, conversation history).
- **Output Tokens**: Tokens generated by the AI model in its response, including reasoning/thought tokens for capable models.
- **Cost Estimation**: Zoo Code automatically calculates estimated cost per API request based on the configured model's pricing, displayed next to token usage in chat history.
- **Auto-Approved Request Limit**: A "Max Requests" setting that limits consecutive API calls Zoo Code can make without explicit re-approval, preventing unexpected expenses.
- **Reasoning Tokens**: For models with thinking/reasoning capabilities (e.g., Gemini 3 Pro Preview), both normal tokens and reasoning tokens are included in cost estimates.
- **Prompt Caching**: A cost-reduction feature where repeated prompts are cached by the provider, significantly lowering both cost and latency for subsequent requests.

## Mental Models
- **Token budgeting**: Think of tokens as a consumable resource—every word in your prompt and every word in the response costs tokens.
- **Cost-aware prompting**: Concise prompts with only relevant context reduce both input and output tokens, directly reducing cost.
- **Circuit breaker pattern**: The auto-approved request limit acts as a circuit breaker, pausing execution before runaway costs accumulate.
- **Model-tier selection**: Use smaller, faster models for simple tasks and reserve larger, more expensive models for complex reasoning.

## Anti-patterns
- **Unbounded auto-approval**: Leaving auto-approval unlimited on complex tasks can lead to unexpected API charges across dozens of sequential calls.
- **Verbose prompts with unnecessary context**: Including entire files when only a function is relevant wastes input tokens and drives up cost.
- **Ignoring reasoning token costs**: Reasoning-capable models include thinking tokens in billing—displayed token counts may be higher than expected.
- **Not using prompt caching**: Repeatedly sending the same system prompt and context without caching available misses significant cost savings.

## Worked Example
**Scenario**: You're working on a complex refactoring task and notice costs climbing.

1. Check token usage in chat history—you see 15,000 input tokens and 8,000 output tokens per request.
2. Set auto-approved request limit to 5 in settings, so Zoo Code pauses before the 6th call.
3. Enable prompt caching (if your provider supports it) to reduce repeated system prompt costs.
4. Switch to a smaller model for simple follow-up questions after the main refactoring.
5. Use Architect mode for code analysis phases where you only need reading, not writing.

## Key Takeaways
1. Token usage (input + output) directly determines cost—be concise and provide only relevant context.
2. Set auto-approved request limits as a safeguard against runaway API costs on complex tasks.
3. Reasoning tokens are billed—cost estimates may be higher with thinking-capable models.
4. Prompt caching and model-tier selection are the most effective cost optimization levers.
