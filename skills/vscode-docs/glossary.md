# Glossary

**Agent** — An AI assistant that can autonomously plan, edit files, run commands, and manage context (Ch 3)

**Agent Harness** — Framework for running agents with specific toolsets and constraints (Ch 4)

**Agent Plugin** — Portable package bundling skills, MCP servers, agents, and hooks following the open standard at agent-plugins.org (Ch 4)

**Approval Workflow** — Human-in-the-loop controls for agent actions before execution (Ch 3)

**Breakpoint** — Marker on a line of code where execution pauses during debugging (Ch 12)

**Build Task** — Automated command defined in tasks.json for compiling, testing, or packaging (Ch 14)

**Call Stack** — List of function calls that led to the current execution point during debugging (Ch 12)

**Code Action** — Quick fix or refactoring suggestion indicated by a lightbulb icon (Ch 2)

**Code Coverage** — Measurement of which lines are executed by tests (Ch 12)

**Code Lens** — Inline information above code showing references, test counts, etc. (Ch 7)

**Code Snippet** — Reusable code template triggered by prefix + Tab (Ch 2)

**Command Palette** — Central access point for all VS Code commands (Ctrl+Shift+P) (Ch 1)

**Conditional Breakpoint** — Breakpoint that only pauses when a specified condition is true (Ch 12)

**Container** — Lightweight, standalone, executable package for software (Ch 10)

**Custom Agent** — Specialized AI persona with specific tool configurations and behaviors (Ch 4)

**Custom Instruction** — Project-specific guidance for AI agents stored in .github/copilot-instructions.md (Ch 3)

**Debug Adapter Protocol (DAP)** — Language-agnostic debugging interface between VS Code and debuggers (Ch 12)

**Debug Configuration** — JSON definition in launch.json specifying how to debug an application (Ch 12)

**Dev Container** — Docker-based development environment defined in devcontainer.json (Ch 10)

**Dev Container Feature** — Reusable component that adds tools to dev containers (Ch 10)

**Docker Compose** — Tool for defining and running multi-container Docker applications (Ch 10)

**Emmet** — Built-in HTML/CSS abbreviation expansion for fast markup (Ch 2)

**Extension** — Add-on that provides additional functionality to VS Code (Ch 1)

**Extension Pack** — Collection of related extensions installed together (Ch 7)

**Extension Recommendations** — Suggested extensions based on project files (Ch 16)

**Focus Mode** — Minimal editor view showing only the code (Ch 2)

**GitLens** — Extension providing advanced Git features like blame and history (Ch 13)

**Hot Code Replacement** — Update code in running debug session without restart (Ch 7)

**Hook** — Shell command that executes at agent lifecycle points (Ch 4)

**Inline Chat** — AI assistance directly in the editor without opening Chat view (Ch 3)

**IntelliSense** — Context-aware code completions, parameter hints, and quick info (Ch 2)

**IntelliSense Mode** — Setting controlling how IntelliSense analyzes code (Ch 9)

**JSDoc** — JavaScript documentation comments that enable better IntelliSense (Ch 6)

**Keybinding** — Keyboard shortcut mapped to a command (Ch 14)

**Launch Configuration** — Debug scenario defined in launch.json (Ch 12)

**Logpoint** — Non-breaking breakpoint that logs messages instead of pausing (Ch 12)

**Markdown** - Lightweight markup language for documentation (Ch 17)

**Merge Conflict** — Incompatible changes in the same location from different branches (Ch 13)

**Merge Editor** — Visual tool for resolving merge conflicts (Ch 13)

**Minimap** —缩略图overview of entire file displayed on the right side (Ch 2)

**Multi-cursor Editing** — Edit multiple locations simultaneously (Ch 2)

**OmniSharp** — Language server providing IntelliSense for C# (Ch 8)

**Port Forwarding** — Redirect network traffic from remote to local machine (Ch 11)

**Profile** — Separate configuration set for different workflows (Ch 1)

**Prompt File** — Reusable prompt template stored in .github/prompts/ (Ch 4)

**Quick Open** - Fast file navigation by name (Ctrl+P) (Ch 1)

**Remote Connection** — Development on remote machine while running VS Code locally (Ch 11)

**Settings Hierarchy** — Default → User → Workspace → Folder settings precedence (Ch 14)

**Settings Sync** — Synchronize settings, keybindings, extensions across machines (Ch 1)

**Skill** — On-demand instructions, scripts, and resources that load when triggered (Ch 4)

**Solution Explorer** — Visual Studio-like project and solution management (Ch 8)

**Source Control Manager (SCM)** — Built-in Git integration with visual interface (Ch 13)

**Staging** — Selecting specific changes to include in a commit (Ch 13)

**Stash** — Temporarily save changes without committing (Ch 13)

**Subagent** — Agent that delegates tasks to other specialized agents (Ch 3)

**Task** — Automated command defined in tasks.json (Ch 14)

**Telemetry** — Data collection about VS Code usage (Ch 16)

**Terminal** — Integrated command-line interface within VS Code (Ch 6)

**Test Explorer** — Visual interface for running and managing tests (Ch 12)

**Test Framework** — System for writing and running automated tests (Ch 12)

**Theme** — Visual styling for VS Code interface and syntax highlighting (Ch 1)

**Timeline View** — File history across commits and saves (Ch 13)

**Tool** — Capability agents can use (file read/write, terminal, search, browser) (Ch 3)

**Tool Set** — Named collection of tools assigned to agents or skills (Ch 4)

**Tunnel** — Secure connection to remote machine without SSH setup (Ch 11)

**Type Checking** — Static analysis of TypeScript code for type errors (Ch 6)

**Virtual Environment** — Isolated Python installation for project dependencies (Ch 5)

**Watch Expression** — Variable monitored during debugging for value changes (Ch 12)

**Workspace** — Project folder opened in VS Code (Ch 1)

**Workspace Trust** — Security model for remote folders (Ch 11)

**Zen Mode** — Distraction-free editing with full screen (Ch 2)

**jsconfig.json** - Project configuration file for JavaScript projects (Ch 6)

**tsconfig.json** - Project configuration file for TypeScript projects (Ch 6)

**devcontainer.json** - Configuration file for Dev Containers (Ch 10)

**launch.json** - Configuration file for debug scenarios (Ch 12)

**settings.json** - Configuration file for VS Code settings (Ch 14)

**tasks.json** - Configuration file for build and automation tasks (Ch 14)
